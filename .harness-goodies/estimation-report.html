Do the story points track the work?

Story points correlate strongly with planned hours, tasks, exclusive commits, raw commits, source lines and phases (Spearman ρ 0.71–0.95) and moderately with code lines and recorded lines (ρ 0.66). There's a catch, though: init calculated these SP values from the same planned hours, or placed them by comparison after delivery.

Key findings

  1. Planned hours are the best match for SP: ρ 0.95 (n=38), and 100% of pairs are in the same order. In the SP 3–40 range the median of planned hours is ~5 per SP (5.0 / 5.2 / 5.2 / 4.7 / 7.3 h per SP at SP 3 / 5 / 8 / 13 / 40).
  2. Removing the noise from lines changed makes little difference. Raw linesAdded+linesRemoved gives ρ 0.66 and Pearson 0.80. Code lines only (source and test files, shared commits split, docs and vendored files left out) give ρ 0.66 and Pearson 0.77.
  3. E0b · Silent Failure Transparency's commits also hold 171,003 lines of committed dependencies (commit c4b8e6dd), which are not counted.
  4. The metrics grow at different rates as SP grows. Each time SP doubles, tasks grow ×1.53, exclusive commits grow ×1.53, planned hours grow ×2.04 and code lines grow ×2.31. SP is close to linear in planned hours, and code lines grow faster than SP.
  5. The planning numbers agree with each other. Tasks vs. hours ρ 0.92. Exclusive commits per task: median 1.08 (IQR 1.00–1.19), so the one-commit-per-task rule is followed.
  6. SP is predictable from the actuals. A combined fit (tasks + exclusive commits + code lines + hours) gives back the exact SP for 47 of 76 features (62%), and 75 are within ±1 scale step. Always answering "5" scores 37% / 72%. The 29 features that are off are listed under re-size candidates.

    Method

    • Source. .harness-goodies/estimations (76 delivered features with an after-delivery SP, of 77 stored) plus git log --numstat in archon-search for the 1,251 unique commits the features reference.
    • SP = updatedStoryPoints, set after delivery. Forecast = storyPoints, set before work starts; 0 features have one.
    • Estimate only. 1 feature has an estimated SP but no after-delivery SP; they appear in Pipeline, All features and the Tasks, Estimated hours and Phases tabs of the Metric explorer, and in no statistic.
    • Commits (excl.) = commits listed only under this feature. Code lines = added+removed lines in source and test files; a commit shared by k features adds 1/k of its lines to each. Source = code files by extension (e.g. .py, .ts, .go, .swift, .java, .sql, .sh, .html, .css) outside test locations. Tests = code files under a test folder (test, tests, __tests__, spec, specs, testing, e2e, …Tests) or named like a test (test_*.py, *_test.go, *.test.ts, *.spec.js, FooTest.java, FooTests.swift, *_spec.rb). Docs = documentation: .md, .mdx, .markdown, .rst, .adoc, .asciidoc files and anything under a docs, doc or documentation folder. Dependencies (not counted) = third-party code and generated pins: node_modules, vendor, third_party, Pods, .venv and similar folders, lockfiles (package-lock.json, yarn.lock, Cargo.lock, go.sum, …) and minified .min.js / .min.css files. Other = everything else: configuration, CI, JSON/YAML data, fixtures, images.
    • Lines changed (stored and recomputed from git) leave out committed dependency files (third-party code and generated pins: node_modules, vendor, third_party, Pods, .venv and similar folders, lockfiles (package-lock.json, yarn.lock, Cargo.lock, go.sum, …) and minified .min.js / .min.css files). The report shows those lines apart as Dependencies (not counted).
    • Spearman ρ with average ranks for ties. The 95% CI is a percentile bootstrap with 2,000 resamples (seed 7). Concordance = (concordant + ½·ties in the metric) ÷ pairs with different SP. Adjacent separation = P(a random feature at the higher SP has a larger metric than one at the lower SP), i.e. the AUC.
    • Power fit: ordinary least squares on ln(metric) ~ ln(SP). Single-metric SP prediction: OLS on ln(SP) ~ ln(metric), rounded to the nearest scale value in log space. Combined fit: the geometric mean of the single-metric predictions from tasks, exclusive commits, code lines and hours. All fits are in-sample.
    • Forecast steps = scale index of the delivered SP − scale index of the forecast; above 0 means the feature came out bigger than estimated.
