## What Has Failed
- **[2026-07-05/07] (×6) Stacked full-suite pytest OOM (2 incidents)**: `-n auto` (14 workers × ~2GB) crashed the 48GB machine; `-n 4` is pinned in `addopts` — never restore `-n auto`/add `-n0` outside debugging. Repeat incident: THREE concurrent full-suite streams (main session auto-backgrounded after 2min + two forks each spawning 4 xdist workers) froze the machine again. Rules: `pgrep -fl pytest` empty before any run (check in MAIN session even while sub-agents are alive); NEVER let two agents each run the full suite — serialize suite-timing/skip-audit investigations in ONE agent; a pytest outliving the 2-min foreground window gets auto-backgrounded by the harness — treat as live, not done; iterate on scoped paths, run full suite once in foreground at task end. **[2026-07-16] (×2) (parallel-worktree)** two git worktrees on the same machine share physical RAM, so the empty-before-run check spans sibling worktrees/agents, not just your own session. **Detector gotcha:** a `pgrep -f "bin/pytest"` wait loop self-matches EVERY waiting shell whose command contains that literal (including its own), so it never terminates and all waiters collide — detect the REAL run by executable, `ps -Ao comm=,args= | awk '$1 ~ /[Pp]ython/ && /bin\/pytest/'`, or the concise `pgrep -fl "Python.*/bin/pytest"`, never pgrep-on-the-bare-pattern. When several agents wait, add a random 10-60s jitter then re-verify clear before launching (thundering-herd guard). Each worktree needs its own `uv sync --dev` (fresh `.venv`). **[2026-07-16] (parallel task-collision)** a sibling agent can COMMIT the very task you're doing (BE-2 landed as commit `dfc198ac` mid-session, its route + your identical test file absorbed) — before implementing, `git log --oneline -5` for a matching `feat(...)` subject and `git ls-files | grep <your-test-basename>`; if present, verify-and-adopt (run its tests + snapshot) rather than re-writing. Also: `git stash`+`stash pop` to A/B a "pre-existing failure" is risky under concurrent commits — the pop can interleave with a sibling's write; prefer a scratch `git worktree` or reading base via `git show HEAD:<file>`.
- **[2026-07-05] (×2) implement-all conventions**: no-bundle rule — adding a required store param does NOT justify bundling caller tasks; use a temporary default in task 1, thread call sites later, remove the default in a cleanup task. Compliance: progress lines in final user-visible text only; check `git status --porcelain` at 100%; fix-agent prompts ≤5 targeted fixes; 10+ → split or apply inline.
