## What Has Failed
- **[2026-07-29] (×12) pytest OOM / parallelism / subagent lifecycle**: `-n auto`(=14) on real-model lanes (`live_benchmark`/`smoke`, ~2GB/worker) OOM-crashed the 48GB machine; addopts is `-n 8` (default suite stubs fastembed, ~0.3GB/worker — never `-n auto`, never `-n0` outside debugging). Suite is I/O-bound on temp LanceDB writes, not CPU — a RAM disk (`bash scripts/test-fast.sh`) beats raising `-n`. Stacked full-suite streams froze the machine twice. Rules: check clear before ANY run with `ps -Ao comm=,args= | awk '$1 ~ /[Pp]ython/ && /bin\/pytest/'` (NEVER `pgrep -fl pytest` — self-matches every waiting shell → thundering-herd deadlock); the harness auto-backgrounds ANY command >~120s regardless of `run_in_background`/`timeout`, so a full suite ALWAYS backgrounds — a subagent that backgrounds its LAST task ends its turn and dies (notification reaches the coordinator, never resurrects it) → subagents run ONLY scoped tests foreground, coordinator runs the full suite; two worktrees share physical RAM so the clear-check spans siblings; iterate scoped, run full suite once at task end.
- **[2026-07-05] (×3) implement-all conventions**: no-bundle — adding a required store param uses a temporary default in task 1, thread call sites later, remove in a cleanup task (never bundle callers). Progress lines in final user-visible text only; check `git status --porcelain` at 100%; fix-agent prompts ≤5 targeted fixes (10+ → split). Recovery-check violations always emit the full Task-failed What/Why/Fix/Prevention block, never a one-liner.
