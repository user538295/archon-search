Rules: `pgrep -fl pytest` empty before any run (check in MAIN session even while sub-agents are alive); NEVER let two agents each run the full suite — serialize suite-timing/skip-audit investigations in ONE agent; a pytest outliving the 2-min foreground window gets auto-backgrounded by the harness — treat as live, not done; iterate on scoped paths, run full suite once in foreground at task end. **[2026-07-16] (×2) (parallel-worktree)** two git worktrees on the same machine share physical RAM, so the empty-before-run check spans sibling worktrees/agents, not just your own session. **Detector gotcha:** a `pgrep -f "bin/pytest"` wait loop self-matches EVERY waiting shell whose command contains that literal (including its own), so it never terminates and all waiters collide — detect the REAL run by executable, `ps -Ao comm=,args= | awk '$1 ~ /[Pp]ython/ && /bin\/pytest/'`, or the concise `pgrep -fl "Python.*/bin/pytest"`, never pgrep-on-the-bare-pattern. When several agents wait, add a random 10-60s jitter then re-verify clear before launching (thundering-herd guard). Each worktree needs its own `uv sync --dev` (fresh `.venv`). **[2026-07-19] (×1) (subagent lifecycle deadlock)** the harness auto-backgrounds ANY command exceeding ~120s regardless of `run_in_background=False` or `timeout=540000`; full pytest suite (10+ min) ALWAYS gets backgrounded — verified across BE-2/BE-3/T-2 subagents: all specified `timeout=540000` yet the suite was backgrounded every time. When a subagent backgrounds its last task, it has no remaining work → turn ends → session terminates; the background notification arrives in the COORDINATOR's session, never resurrecting the dead subagent. FIX: subagents must run ONLY scoped tests (`uv run pytest tests/test_X.py --no-cov -q`, finishes < 30s, stays foreground); coordinator runs the full suite if needed. Also: `pgrep -fl "Python.*/bin/pytest"` in a wait loop self-matches its own shell (argv contains the literal string) → loop never exits — use `ps -p <specific_pid>` instead. **[2026-07-16] (×1) (parallel task-collision)** a sibling agent can COMMIT the very task you're doing (BE-2 landed as commit `dfc198ac` mid-session, its route + your identical test file absorbed) — before implementing, `git log --oneline -5` for a matching `feat(...)` subject and `git ls-files | grep <your-test-basename>`; if present, verify-and-adopt (run its tests + snapshot) rather than re-writing. Also: `git stash`+`stash pop` to A/B a "pre-existing failure" is risky under concurrent commits — the pop can interleave with a sibling's write; prefer a scratch `git worktree` or reading base via `git show HEAD:<file>`.
