# Learnings

## What Has Failed
- **[2026-07-05/07] Stacked full-suite pytest OOM (2 incidents)**: `-n auto` (14 workers × ~2GB) crashed the 48GB machine; `-n 4` is pinned in `addopts` — never restore `-n auto`/add `-n0` outside debugging. Repeat incident: THREE concurrent full-suite streams (main session auto-backgrounded after 2min + two forks each spawning 4 xdist workers) froze the machine again. Rules: `pgrep -fl pytest` empty before any run (check in MAIN session even while sub-agents are alive); NEVER let two agents each run the full suite — serialize suite-timing/skip-audit investigations in ONE agent; a pytest outliving the 2-min foreground window gets auto-backgrounded by the harness — treat as live, not done; iterate on scoped paths, run full suite once in foreground at task end.
- **[2026-07-05] E2d BE-1 no-bundle rule**: adding a required store param does NOT justify bundling caller tasks into one commit. Use a temporary default (`ns: str = DEFAULT_NAMESPACE`) in task 1, thread call sites in later tasks, remove the default in a cleanup task.
- **[2026-06-28] session-limit / oversized agents**: an agent returning "session limit" with zero tool uses → respawn with identical prompt (work was well-specified, only wall-clock failed). Keep fix-agent prompts ≤5 targeted fixes; for 10+, split sequentially or apply directly in main context.
- **[2026-07-05] /implement-all literal compliance failures**: (1) Progress lines MUST appear in the final user-visible text message of each iteration — mid-turn text between tool calls may not display; copying them just before the Agent launch is not enough. (2) Violations MUST be filed in the exact structured format (`- Task [N.M] failed ❌: What / Why / Fix / Prevention`) — prose summaries do not satisfy the requirement. (3) After the plan reaches 100%, check `git status --porcelain` before declaring done — late background agents can leave uncommitted changes.

## What Has Worked
- **[2026-07-07] T-4 subprocess e2e — avoid recursive self-invocation**: a subprocess test that runs `pytest <same_file>` includes itself in collection, spawning infinite subprocess chains. Fix: use `-k "test_a or test_b"` to select only the two target tests by name. The outer test (`test_e2e_eval_gate_synonym_bridge_and_negative_control`) is never matched by `-k` so no recursion. Went GREEN on first run (33s). Pattern: `@pytest.mark.integration` + `@pytest.mark.xdist_group("benchmark")`; `_PROJECT_ROOT = Path(__file__).resolve().parents[2]` for `tests/eval/` depth.
- **[2026-07-07] BE-8 adding a new EvalMetrics field**: four atomic locations must update together: `EvalMetrics` in `types.py`, `_RENDERED_QUALITY_FIELDS` + `EvalQualityFloors` + `_optional_float_fields` + `EvalMetrics` constructor in `run_eval_suite` + `_QUALITY_FLOOR_FIELDS` all in `runner.py`, `_QUALITY_METRIC_FIELDS` in `test_eval_suite.py`, `_QUALITY_FIELDS` in `test_baseline_contract.py`. After adding the field: (1) run 3 calibration passes (`uv run python tests/eval/baselines/regenerate.py`-equivalent), (2) update `thresholds.toml` floors (may shift `routing_mrr_centroid/hybrid` when corpus changes), (3) add waivers to `baseline.json` for floors set >0.05 below baseline, (4) run `regenerate.py` to refresh `thresholds_hash`. A floor drop in existing metrics caused by corpus expansion (e.g. routing centroid shift) must be updated in `thresholds.toml` immediately — `assert_thresholds` will fail the gate if floor > actual. **Negative-control twin test**: `test_eval_gate_hotpotqa_negative_control_unchanged` is distinct from `test_eval_gate_graph_negative_control_recall_at_5` — the former uses `build_communities_for_eval` + `eval_tmp_lancedb_root` to assert the floor holds WITH synonym edges active; the latter runs without lancedb_root (stub expander). Both are needed: one gates the non-synonym path, the other gates that synonym expansion doesn't harm simple queries.
- **[2026-07-06] BE-7 synonym edge truncation exemption pattern**: synonym edges (relationship_type='synonym_of') need TWO separate exemptions in `_truncate_graph`: (1) node-cap exemption — collect synonym endpoint IDs before the cap, add them to `nodes_out` after the top-N slice (exempt from cap); (2) edge-cap exemption — split edges into synonym/non-synonym lists, apply `max_edges` only to sorted non-synonyms, append synonym edges after. - **[2026-07-06] BE-2 LanceDB async vector search API**: `AsyncTable.search()` IS a coroutine (must be awaited); `AsyncTable.vector_search()` is NOT (returns `AsyncVectorQuery` synchronously). `AsyncVectorQuery` has `.distance_type(metric)` not `.metric(metric)`. Correct chain: `nodes_table.vector_search(emb).distance_type(metric).limit(n).where(pred).to_arrow()`. When `ns` is the last param but `metric` has a default before it, use `*` keyword-only separator: `metric: str = "cosine", *, ns: str` — required keyword-only, no default, no SyntaxError.
- **[2026-07-05] xdist stub / sys.modules isolation**: any file installing a stub into `sys.modules` (e.g. `fastmcp`, `spacy`) at module level MUST restore the real class at module level immediately — `--dist=loadgroup` imports every file in every worker at collection, so fixture teardown is too late and leaks poison all workers. To simulate an absent package, set `sys.modules["pkg"] = None` and restore in `finally`.
- **[2026-06-29] asyncio in xdist workers**: always use `asyncio.run(coro)` (or `@pytest.mark.asyncio`); `get_event_loop().run_until_complete()` raises in xdist workers. `asyncio.run()` is safe from the main test thread inside `with TestClient(app):` (app runs in its own loop).
