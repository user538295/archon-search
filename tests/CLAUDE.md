# Testing rules

The two safety rules (parallel `-n 8`, never `-n auto`; one test suite at a time) are stated only in this file: root `CLAUDE.md` just points here. Everything else about testing is here too. Marker descriptions and the rationale for `norecursedirs` / `-n 8` / `--cov-fail-under=85` live as comments in `pyproject.toml` `[tool.pytest.ini_options]` — read those, don't duplicate them. Strategy and coverage policy: `Documentation/Architecture/200_testing_strategy.md`.

## Running

```bash
uv run pytest                                   # full default suite
bash scripts/test-fast.sh                       # macOS RAM disk, ~24 s quicker; extra args pass through
TMPDIR=/dev/shm uv run pytest --basetemp=/dev/shm/archon-pt   # Linux/CI equivalent
uv run pytest tests/test_x.py --no-cov          # scoped, while iterating
uv run pytest -n0 -x tests/test_router.py::test_name          # serial — developer debugging ONLY
```

`scripts/test-fast.sh` refuses to start if another pytest is running (OOM guard) and always tears the RAM disk down, even on Ctrl-C. `--no-cov` is a CLI-only override — never bake it into `addopts`.

Lanes excluded from the default run (`norecursedirs` primary, `-m` filter secondary):

```bash
uv run pytest -m live_benchmark tests/eval/live_benchmark/ --no-cov   # needs the model cache
uv run pytest tests/smoke/ --no-cov                                   # spawns a real `archon-search serve`
uv run pytest tests/smoke/docker/ --no-cov                            # covered by the same tests/smoke exclusion
uv run pytest tests/eval/live/ --no-cov                               # real model weights; hangs if auto-collected
uv run pytest -m docling --no-cov                                     # `-m` filter only — not a dedicated directory
ARCHON_SEARCH_DATA_DIR="$HOME/.archon-search" uv run pytest -o addopts= --strict-markers --strict-config --no-cov -n0 -m graph_real_artifact  # real GLiNER checkpoint must be pre-downloaded there
ARCHON_RUNTIME_PARITY_DATA_DIR=/tmp/rt_data uv run pytest -m runtime_parity tests/runtime_parity/ --no-cov -q -p no:cacheprovider -o addopts= -rP  # real PyTorch weights vs frozen fastembed outputs; downloads ~15 GB on first use
ARCHON_SEARCH_RUN_DOCKER_SMOKE=1 uv run pytest tests/test_docker_smoke.py -n0 -o addopts= --no-cov   # builds the image and runs it (docker daemon; skipped without the env var)
ARCHON_SEARCH_API_KEY=<running server key> uv run pytest tests/benchmark_routing_latency.py -n 0 -v -s   # HTTP /route latency against a running server; -n 0 is required (xdist workers inherit the conftest's test key, so every call is a 401)
uvx ruff@0.17.3 check .                                               # the lint step CI runs before the tests; zero findings
```

The unlocked-dependency lane re-runs the default suite and the docling/graph lanes in a throwaway venv with the newest dependency versions end users install (`uv.lock` ignored). It fails if a test changes that venv, and a child `uv run` would silently test `uv.lock`'s versions instead — so never let a test run a real package install or `uv run`; spawn a child pytest as `sys.executable -m pytest`:

```bash
bash scripts/test-unlocked-deps.sh            # install + suite + docling + graph; or one step by name
```

The smoke lane's server subprocesses run on a throwaway `ARCHON_SEARCH_DATA_DIR`, but `_link_model_cache` (`tests/smoke/conftest.py`) symlinks their `models/` at the fixed `~/.archon-search/models` (`_SHARED_MODELS_DIR`, not the shell's `ARCHON_SEARCH_DATA_DIR`) — the server's model caches derive from its data dir (`paths.py`), so without the link each run would re-download ~1.3 GB of weights and the lane's latency budgets would be network-bound. First run on a cold host pays that download once, into the shared cache. `smoke_server` also writes `archon-search.toml` under that data dir (`_write_fake_llm_config`: `[hyde]`, `[rag_fusion]`, `[openai_shim] enabled = true`), the first two aimed at the session-scoped `smoke_fake_llm` (a `FakeModelServer`); the smoke test files are `test_cli.py`, `test_rest.py`, `test_conftest.py`, `test_s04_health_after_stop.py`, `test_t3_guards_fail_in_real_pytest_run.py`, `test_four_interface_parity.py`, `test_cli_search.py`, `test_hyde_rag_fusion_fields.py`, `test_top_k.py` and `docker/test_docker_cli.py`.

## PARALLEL TESTS ARE MANDATORY

`addopts` sets `-n 8 --dist=loadgroup`. Never `-n auto` (=14 here) and never `-n0` in a normal run: `-n auto` on the real-model lanes (`live_benchmark`/`smoke`, ~2 GB/worker) OOM-crashed the 48 GB machine on 2026-07-05. `-n0` disables parallelism and is reserved for developer debugging. For more failure detail use `--tb=short` / `--tb=long`, never `-n0 -s`.

Release CI (`archon-search-release.yml`, `archon-search-pr.yml`) passes `-n0` explicitly: it uses multi-step `--cov-append` across separate invocations, and xdist's per-invocation combine step would corrupt the accumulated `.coverage` file.

## ONE TEST SUITE AT A TIME

Never launch `uv run pytest` fire-and-forget (`run_in_background` without `Monitor`). Subagents may use `run_in_background: true` + `Monitor` to outlast the ~120 s Bash foreground ceiling — `Monitor` watches the process so nothing is abandoned. Before any run, verify no workers are alive:

```bash
ps -Ao args= | grep -E '[/]bin/pytest|[u]v run pytest'
```

Match on `args`, never `comm` (macOS truncates a Homebrew interpreter to `/opt/homebrew/Ce`, so the older `awk '$1 ~ /[Pp]ython/'` form reports "no workers" mid-suite). `pgrep -fl pytest` self-matches the shell. Stacked runs multiply workers and OOM-crashed the 48 GB machine on 2026-07-05.

While iterating, run scoped paths; run the full suite once at task completion and always report its wall-clock duration (last measured: ~151 s, default `addopts` with coverage, `-n 8`, 16654 tests collected by `uv run pytest --collect-only -q`, 2026-11-03; ~370 s before that day's slow-test fixes).

An error that pytest reports as an unraisable exception (`PytestUnraisableExceptionWarning`, a `ResourceWarning` from an unclosed transport) names the test that was running when the garbage collector finalised the object, not the test that leaked it: pytest forces a collection only at the end of the session. When such an error shows up in one full run and not in the next, run `uv run pytest -p tests._gc_each_test_plugin` (about five times slower): it collects after every test and reports the exception against the leaking test. The full suite was run that way on 2026-11-02 (15933 passed, 24 skipped, no warning), so a new occurrence is a new leak; the one that had been hiding was anyio's cancelled-connection leak (DEP-3 in doc 530).

## Suite layout

- `tests/` — unit tests. The autouse fixture `_stub_model_backends` (`tests/conftest.py`) patches `ModelEmbedder.encode` (zero vectors of the spec's dimension) and `ModelReranker.predict` (uniform 0.5), replaces `llm_client.token_counter.load_gpt2_tokenizer` with the `tests/_token_counter_stub.py` stub, and replaces `install.prewarm.ensure_model` (the install pre-warm's Hugging Face download) with a stand-in that reports the snapshot as present, so no torch, transformers, weights or model downloads load; construction is not stubbed, so tests must use model names from the registry (`archon_search/model_specs.py`). The graph model is not stubbed that way: a test that fakes `gliner` calls `seed_graph_model_snapshot()` (`tests/_graph_engine_stub.py`) so its snapshot is a cache hit. `tests/_search_stubs.py` only sets thread env defaults and fakes `chonkie`. A test of the real PyTorch code path opts out with a module-level `pytestmark = pytest.mark.real_torch_backends` and runs on the tiny synthetic snapshots of `tests/_tiny_encoder.py` (no weights, no network); the real-weights lanes (`live_eval`, `live_benchmark`, `runtime_parity`) are opted out by their own marker.
- Autouse `_reset_warn_once` (`tests/conftest.py`) clears the process-wide `archon_search.llm_client.once_per_process` state around every test, so a test that makes a provider fail sees its one-per-process WARNING whatever ran before it on the same xdist worker.
- The session guard `_block_model_providers` (`tests/conftest.py`, rules in `tests/_model_host_guard.py`) keeps default-lane tests off real model providers, whatever the developer's shell holds. It refuses: constructing an `anthropic` client (always), or an `openai` or `ollama` SDK client unless it is aimed at a loopback server a test started (a `FakeModelServer` or an `unreachable_port()` of `tests/_fake_model_server.py`) or bound to an injected in-process client (`http_client` for `openai`, `transport` or `mounts` for `ollama`); a request through the real network transports of `httpx` or `httpx2` (the Hugging Face hub, `openai` and `anthropic` use `httpx2`) to a non-loopback host or to a loopback default model-server port (Ollama 11434, llama-server 8080); a spawn of a `claude` binary other than a fake installed by `tests/_fake_claude.py` (so every real install is refused), of `claude` by bare name, of the real binary found on `PATH` at session start (symlinks followed), or of a shell command line that names `claude`. In-process transports (`httpx.MockTransport`, `ASGITransport`) are never touched. Not covered: `urllib`, `requests`, `aiohttp` and `hf_xet` traffic, and a launcher in front of `claude` (`env claude`). A refusal is a `RuntimeError` that production code catching `Exception` can absorb, so the guarantee is that nothing leaves the machine, not a red test. The conftest hook `pytest_runtest_setup` lifts the guard, module- and session-scoped fixtures included, for tests marked `live`, `live_eval`, `live_benchmark`, `runtime_parity`, `smoke`, `docling` or `graph_real_artifact` (`set_suspended` lifts every guard except the `anthropic` client one, which stays in force); `live` is not excluded from the default run, so such a test runs there with the `openai`, `ollama`, network and `claude` guards lifted (it still skips without a key, see below). The integration `anthropic` stub (`tests/integration/conftest.py`) refuses `AsyncAnthropic()` with the same message; a test that needs a client patches that attribute.
- `tests/_fake_model_server.py` `FakeModelServer` is a loopback stand-in for both local servers: Ollama (`POST /api/chat`, `POST /api/show`, `GET /api/tags`) and llama-server (`GET /props`, `GET /v1/models`, `POST /tokenize`, `POST /apply-template`, `POST /v1/chat/completions`); `requests_to(path)` returns what a path received. It can also hold a model answer: `hold_chat=True` (or `hold()` later) makes the chat endpoints record a request on arrival and answer only after `release()`; `reply_text` is a public attribute read when the held request is answered. Its server class `ClientDisconnectQuietHTTPServer` prints nothing when a client resets a kept-alive connection (the handler thread outlives `server_close`, and the reset arrives in a later test, where the traceback hit a closed stderr and pytest reported a thread exception). `unreachable_port()` is a down server: a connection to it is refused at once. Never stand in for one with a socket that is bound but not listening: macOS drops the connection attempt and the call hangs about 8 s. Run a test's own `socketserver` server with `tests/_threaded_http.py` `serving_in_thread(server)`: it polls for `shutdown()` every 10 ms instead of `serve_forever`'s 500 ms, which every exit would otherwise wait out. `tests/server/test_http_cancel_leaks_no_transport.py` guards the `anyio>=4.16.0` floor (DEP-3 in doc 530): a cancelled `httpx` request must leave no unclosed transport. `tests/_cli_testclient_bridge.py` `cli_against_app(client, token, monkeypatch)` runs CLI commands (`cli.invoke(collection, ["info", name])`) against the in-process `TestClient` app instead of a socket (no redirects followed, `timeout=` dropped, `httpx.Client`/`stream` raise; see its docstring).
- `tests/_fake_claude.py` `install(tmp_path, reply=...)` puts a REAL subprocess in place of the `claude` binary for `ClaudeCliClient` tests (argv, environment, working directory and standard input are recorded in `fake.invocations()`; POSIX only); it is the only way a test may spawn `claude` under the guard above. `tests/_description_stubs.py` supplies `fake_lifecycle` (fixed ticket) and `recorded_lifecycle` (the real `DescriptionLifecycle` over a scripted generator and the real guarded `DescriptionWriter`) for pipeline tests that inject `description_lifecycle=`; `tests/_description_text_cases.py` holds the texts a description is refused for, shared by the rule's unit test and the route tests.
- `tests/services/` — tests of the application layer `archon_search/services/` (search budget, request HyDE, validators, service errors, search command, the search service including its multi-collection and telemetry tests, container, authz policy), plus the check that the old `server` modules no longer import.
- `tests/parity/` — the interface-parity registry (`registry.py`, plain data) and its test (`test_parity.py`): every live REST route, MCP tool and CLI command must be claimed or waived there, and a pending waiver must name its roadmap slice. The field-level check beside it (`field_parity.py` the check and the live-schema collectors, `field_registry.py` the plain-data mapping, `test_field_parity.py` synthetic-mapping unit tests plus one run on the real tree) compares the search command's fields with the REST request model, the MCP tool's input schema and the CLI options, and the service result's fields with the REST and MCP response models; a field a surface lacks needs a waiver with a reason, and a surface field no mapping names fails. Not `tests/runtime_parity/` (PyTorch against frozen fastembed outputs).
- `tests/test_layer_import_boundary.py` — the layer import-boundary guard: `services/` imports nothing from `server/`, `cli/` or the web, CLI and HTTP-client packages; `server/` files import no route module or `server.mcp` (`app.py` excepted); a CLI command module imports only `cli/_helpers.py`; the CLI imports no `services/` or `server/` (the lazy `run_server` in `cli/serve.py` excepted). Known violations sit in a ratcheting allowlist (a new or a stale entry fails), and the same file fails any import of a moved authz name from `server/authz`. Like `tests/parity/`, it stays free of repo-conftest dependencies, and `tests/smoke/test_t3_guards_fail_in_real_pytest_run.py` (local smoke lane) shows each guard failing in a real pytest process.
- `tests/test_adapter_thinness.py` — the adapter-thinness AST scan: `server/routes_search.py` and `server/routes_openai_shim.py` (whole module) and the `search` tool body in `server/mcp.py` must not use `services.validators`, `services.request_hyde`, `services.search_budget` or `telemetry.entry`, which `SearchService` owns. A syntactic scan with documented blind spots (dynamic imports, module aliases); it leaves the allowlist of `test_layer_import_boundary.py` alone.
- `tests/integration/` — real `SearchStore` / `SearchPipeline` / LanceDB in `tmp_path`, `TestClient` against a real app. Marked `integration`, run by default. Shared helpers (`make_real_app`, `serve_real_app`, `ingest_doc`, `ingest_file_via_path`, `search`, `make_real_pipeline`) live in `tests/integration/conftest.py` — do NOT modify `tests/conftest.py` when adding integration tests. The job scheduler of a `make_real_app` / `serve_real_app` app ticks every 0.1 s (`REAL_APP_SCHEDULER_TICK_SECONDS`, passed as `JobScheduler(tick_seconds=...)`; production ticks every 5 s), so a queued export, import or migration starts at once. `serve_real_app` puts the same real app behind a real uvicorn socket (`tests/_uvicorn_server.py` `serving(app)`: lifespan included, no signal handlers, no logging configuration touched): use it, with `httpx` or a raw socket, for what an in-process `TestClient` cannot show, such as a client that closes its connection mid-request (`test_disconnect_cancels_provider_call_e2e.py`). Never prove an absence with a fixed sleep: let the event loop run a fixed number of turns (`await asyncio.sleep(0)`) or wait on an event with a generous bound.
- `tests/eval/` — the sanctioned regression gate for retrieval / reranking / routing / latency changes. Deterministic, corpus-aware but label-blind backends (`archon_search/eval/backends.py`) keep metrics stable without real weights; latency p50/p95 is a regression guard, not a production SLA. Read `tests/eval/README.md` before touching `thresholds.toml` or fixtures. A full-corpus run takes 10-20 s, so a test that only reads a report takes a shared measurement from `tests/eval/conftest.py`: `measured_eval_report` (no LanceDB root) or `measured_graph_eval` (a `GraphEvalMeasurement`: the report and the LanceDB root holding the graph fixture). Such a test carries `@pytest.mark.xdist_group("eval_report")`, so the suite is measured once per run, never mutates the report, and checks it against thresholds through `attach_gates(report, thresholds_path, baseline_path)`, which returns a copy. Measure afresh (`measure_eval_suite`) only when the test is about the run itself (determinism, comparison with another run).

`eval` tests run by default because `--thresholds-path tests/eval/thresholds.toml` is in `addopts`; they skip only when invoked without it. `live` tests always skip on default runs because the autouse fixture in `tests/conftest.py` clears `ANTHROPIC_API_KEY` (this removes a 30 s SDK-timeout floor). To run them for real against the Anthropic API, temporarily comment out that `monkeypatch.delenv` line and the `_patch_anthropic(stack)` call in `tests/_model_host_guard.py` — every invocation loads the root conftest, so there is no shell-level workaround.
