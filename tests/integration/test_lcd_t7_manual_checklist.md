# Manual Test: LCD T-7 — Live descriptions on every provider and real `think` behaviour

Plan task T-7 of `Documentation/Backlog/2026-10-30-010-llm-collection-descriptions-tasks.md`; covers the live arms of S50, S53 and S54 of `Documentation/Backlog/2026-10-30-010-llm-collection-descriptions-team-plan.md` (descriptions on `ollama`, `llama_cpp`, `claude_cli`, `anthropic` and `openai`; the Ollama context change; the `think` setting on a real reasoning model). The automated tests in `tests/integration/test_lcd_t7_bad_output_e2e.py` (`test_e2e_thinking_only_output_stores_failed_keeps_old_description`, `test_e2e_overlong_answer_stored_trimmed_to_one_line_within_600`, `test_e2e_cloud_retry_sends_excerpts_twice`, `test_e2e_think_setting_rides_on_every_ollama_call_retry_included`) drive the real app against `tests/_fake_model_server.py`; they cannot show what a real model, a real `claude` login or a real cloud account does with the same prompt.

**Executed on 2026-11-01 (results at the end; the real-model run found one product defect, fixed in commit `76a3336d`: the 1024-token answer ceiling let a reasoning model return only thinking).** The commands were written against the code as implemented (`archon_search/description_generator.py`, `archon_search/description_lifecycle.py`, `archon_search/llm_client/*_client.py`, `archon_search/server/llm_composition.py`, `archon_search/cli/collection.py` `info`). The cloud arms D and E could not run (no cloud key on the test machine) and stay unproven.

**What was observed while writing this checklist (2026-10-31, development machine; no server was started and nothing was ingested):** `ollama` 0.40.13 has `qwen3.6:35b-a3b-128k` (about 24 GB) and `llama3.1:8b`; `claude` 2.1.308 and `llama-server` 0.7.0 (`llama-server --version`) are installed. No cloud key, no `claude` login test and no llama-server model were exercised.

## 1 — Live descriptions on every provider (S50, S53)

**Why manual:** needs real models (`ollama`, `llama-server`), a real `claude` login and cloud keys; the automated tests answer from a fake server, so they prove the plumbing and the output rules but not that real text is sensible or that a changed Ollama context really reloads the model.

**Steps (A to E and the two Ollama arms; each starts from a first ingest as described in the prerequisites; for every provider that gives text also run the length command, its output must show one line of 600 characters or fewer and no `<think>`-style tag; an over-long first answer is retried once by design and is not visible in the stored text, the automated test covers it):**
- [x] A, `ollama`: `[description]` = `enabled = true`, `provider = "ollama"`, `model = "llama3.1:8b"`, `ollama_context_tokens = 4096`, `timeout_seconds = 120.0`. Ingest, wait, read, run the length command. Expected: status `ok`, source `generated`, a one-line description of at most 600 characters that talks about the corpus (not about the prompt), and no WARNING from `archon_search.description_generator` in `/tmp/lcd-t7/server.log`. The generator logs nothing but WARNINGs, so `grep -c "description_generator" /tmp/lcd-t7/server.log` prints `0` for a clean run; the positive control for that grep is a deliberate failure (a wrong `model` name makes the status `failed` and the grep print `1`). A run with `ollama_context_tokens` unset logs the one assumed-window WARNING from the startup composition instead (`grep -i "context" /tmp/lcd-t7/server.log`).
- [x] A2, context change (S50): continue from A on the same collection. Stop the server, set `ollama_context_tokens = 8192`, start it and wait for `/ready`, copy `/tmp/lcd-t7/more/*` into `/tmp/lcd-t7/corpus/`. IMMEDIATELY before the ingest run `ollama ps`: it must list `llama3.1:8b` with `CONTEXT` 4096 (the reload precondition; Ollama unloads an idle model after about five minutes, and the restart may have taken that long; if the list is empty or the model shows another context, rerun A and be quicker, otherwise the later `8192` proves nothing). Ingest again (the growth asks for a new description) and run `ollama ps` right after the status leaves `pending`. Expected: `CONTEXT` reads `8192` (the model was reloaded with the new window), the description is regenerated with status `ok`, and the second call worked. A `CONTEXT` that still reads 4096 means the model was not reloaded: record it as `fail`.

The input budget is then small (about (2048 - 1024) / 1.2 minus the template, in gpt2 tokens), so the sample is a few excerpts. Expected: status `ok`, no `failed` with a window message, and in the Ollama server log (`~/.ollama/logs/server.log` on a macOS app install; the wording differs between releases) no `truncating input prompt` line for the call; record the log evidence as `n/a` when that log is not reachable.

Check the login without loading this repository's project files: `cd /tmp/lcd-t7 && env -i PATH="$PATH" HOME="$HOME" USER="$USER" LOGNAME="$LOGNAME" TMPDIR="${TMPDIR:-/tmp}" LANG="${LANG:-en_US.UTF-8}" claude -p 'Reply with one word: ok'` (a logged-out binary prints `Not logged in`). `[description]` = `enabled = true`, `provider = "claude_cli"`, `timeout_seconds = 120.0` (a blank `model` is the claude default). ## 2 — Real `think` behaviour on a reasoning model (S53, S54)

**Why manual:** needs a real reasoning model such as `qwen3.6:35b-a3b-128k` (about 24 GB; whether the thinking switch works and whether the answer ceiling (the 1024-token reserve plus the 3072-token thinking headroom of `DESCRIPTION_THINKING_HEADROOM_TOKENS`) lets a thinking model finish can only be judged on a model that really thinks). The automated tests show what is sent on the Ollama wire and what happens to a thinking-only answer, not what a real model does with it.

**Steps (each arm, unless it says otherwise: a first ingest of `/tmp/lcd-t7/corpus`, `[description]` = `enabled = true`, `provider = "ollama"`, `model = "qwen3.6:35b-a3b-128k"`, `ollama_context_tokens = 8192`, `timeout_seconds = 300.0` plus the `think` line of the arm; note the seconds from the ingest until the status leaves `pending`):**
- [x] `think = false`: Expected: status `ok`, a normal one-line description, the call is the quickest of the three arms. No WARNING from `archon_search.description_generator`.
- [x] `think = true`: Expected: status `ok` and a clean one-line description (the thinking is returned apart from the answer or removed by the output rules); the call takes longer than the `false` arm. A status `failed` with the WARNING that points to the `think` setting ("set `think` to false") means the model spent the answer ceiling (1024 tokens plus the 3072-token thinking headroom) on thinking; that contradicts S54, so record `fail` with the model and the seconds.
- [x] `think = "default"`: Expected: status `ok`; nothing about thinking is sent, so the model's own default applies. Note which of the two arms above the duration matches. A `failed` status with the `think` WARNING here means the model thinks by default and the answer ceiling (1024 tokens plus the 3072-token thinking headroom) cut it off: that contradicts S54 (the ceiling lets a reasoning model finish), so record `fail` with the evidence, do not excuse it.
- [x] Unsupported model with `think = true` (S54), one process, two generations: `model = "llama3.1:8b"`, `ollama_context_tokens = 4096`, `think = true`. First ingest `/tmp/lcd-t7/corpus`, then copy `/tmp/lcd-t7/more/*` into it and ingest again (a second generation in the same server process). Expected: status `failed` after the first ingest (there is no earlier description to keep) and after the second, no retry, and exactly one WARNING per server process naming the model: `grep -c "has no thinking mode" /tmp/lcd-t7/server.log` prints `1` and the line reads `[description].think is true but the model 'llama3.1:8b' has no thinking mode; set think to "default" or false`. To also see the "earlier description is untouched" half, run the same two ingests first with `think = false` (status `ok` after the first), restart with `think = true`, copy `more/*` and ingest again: the status becomes `failed` and the earlier description is still shown.
- [x] (`claude_cli` only; `openai`/`anthropic` BLOCKED: no cloud key) `think` ignored by cloud and `claude_cli` (S54): with `provider = "claude_cli"` (or `openai` / `anthropic`) and `think = true`, a description still generates (status `ok`); the value has no effect (the automated cloud test already shows that no `think` field reaches an `openai` request). The startup WARNING for an ignored `think` now exists (`archon_search.server.description_startup`): `[description].think = true is ignored for provider claude_cli, which has no thinking switch; set think to "default" (or remove it)`; it was observed in the server log on the `claude_cli` run.
- [x] `llama_cpp` thinking switch (S54): with a thinking-capable `.gguf` model on `llama-server` (0.7.0 lists `--chat-template-kwargs` and `--reasoning` in `llama-server --help`; run it with the model's chat template enabled), `think = false` must give a quick direct answer and `think = true` a slower one with a clean description. Record the model; write `n/a` when no thinking-capable `.gguf` model is at hand.

**Pass criterion:** `false` answers directly; `true` and `default` end with a clean one-line `ok` description within the answer ceiling (1024 tokens plus the 3072-token thinking headroom); `true` on a model without thinking support gives status `failed` with the single WARNING naming the model. A `true` or `default` arm that ends `failed` with the `think` WARNING FAILS the S54 claim that the ceiling lets a reasoning model finish: record it as `fail` and note the model and the seconds.

## Acceptance

Accept when item 1 passes for all five providers and item 2 passes on a real reasoning model: sensible one-line descriptions within 600 characters, a changed Ollama context reloads the model with calls still working, `think` behaves as documented for `true`, `false` and `default`, and an unsupported `think = true` fails cleanly with one WARNING.
