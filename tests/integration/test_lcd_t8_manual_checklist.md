## Prerequisites

- `uv`, a shell, and for the success arms network access. Run from the repository root; use the checkout's `.venv/bin/archon-search` for the arms that install nothing (`uv sync --dev` first; `.venv/bin/python -m pip` does not exist, which the failed-install arms rely on) and a scratch virtualenv for the arms that really install extras (section 4). WARNING: in the checkout `.venv`, answering `y` at `Proceed?` WITHOUT the fake `uv` of section 3 runs a real `uv pip install --python .venv/bin/python archon-search[...]` against the development environment; every arm that answers `y` there is written with the shim, or with a scratch venv, for that reason.
- Isolation. A real wizard run does more than write the TOML: after the installs it registers and starts the managed service. On macOS that is `~/Library/LaunchAgents/com.archon.search.plist` with the fixed label `com.archon.search` (`archon_search/platform/macos.py` `_LABEL`); on Linux the user systemd unit `~/.config/systemd/user/archon-search.service`, registered with `systemctl --user enable` and `loginctl enable-linger $USER` (the linger setting is NOT undone by `uninstall`). It REPLACES an installed archon-search service on this machine. Only the arms that end at `Proceed? n`, at the disk-space abort, or that run with `--dry-run` leave the service alone; the other arms (sections 3, 4) register it: run them on a machine or user account without an installed service, or accept that the installed service is replaced and re-run the real wizard afterwards. Clean up with `.venv/bin/archon-search uninstall` IN THE SAME SHELL with the same exports (stops and unregisters; keeps the scratch data; on macOS `unregister` also removes `get_data_dir()/run-server.sh`, which without `ARCHON_SEARCH_DATA_DIR` is the real installation's wrapper). `~/.archon-search` is not written to while `ARCHON_SEARCH_DATA_DIR` is set.
- Per walk a fresh scratch data directory: `trash /tmp/lcd-t8/<walk>` when it exists, `mkdir -p /tmp/lcd-t8/<walk>`, then `export ARCHON_SEARCH_DATA_DIR=/tmp/lcd-t8/<walk>` and `export ARCHON_SEARCH_CONFIG=/tmp/lcd-t8/<walk>/archon-search.toml` (or pass `--config` as in the commands; both name the same file). Unset `ARCHON_SEARCH_PORT`, `ARCHON_SEARCH_HOST`, `ARCHON_SEARCH_KEY_FILE`, `ARCHON_SEARCH_API_KEY`, `ARCHON_SEARCH_CONTAINER` (the wizard ignores it, but `uninstall`, `start` and `stop` refuse while it is `1`) and `ANTHROPIC_API_KEY` (a set `ANTHROPIC_API_KEY` hides the key tip of section 4; `OPENAI_API_KEY` does not, but unset it so no run picks it up by accident). The key file of the walk is `$ARCHON_SEARCH_DATA_DIR/.search.env` and the secrets file `$ARCHON_SEARCH_DATA_DIR/.secrets.env`.
- Logging. With `ARCHON_SEARCH_DATA_DIR` set the server log of a registered service is `$ARCHON_SEARCH_DATA_DIR/logs/archon-search.log`; the environment overrides `[database] db_path` and `[logging] log_file`. The wizard itself prints to the terminal; read the log only for the service-start check of section 4.
- Ollama arms need a running Ollama with at least one model (`ollama list`), so the wizard offers the numbered model picker (`Installed Ollama models:`). With no model or no server the wizard prints `No models available from http://localhost:11434.` and asks for a free-text model name; the answer lists below assume the picker and say what changes otherwise.
- Common answer prefix of every interactive walk below, after `--profile minimal --no-multilingual --disable-gpu --skip-preload`: `Index code files (installs tree-sitter + graph enrichment, enables graph)? [y/n]:` n, `Keep reranker enabled? [y/n]:` y, `Auto-watch directories and re-index on file changes? [y/n]:` n, `Enable local query telemetry? [y/n]:` n, `Also pre-load every per-collection embedding model at startup? [y/n]:` n, `Routing strategy (centroid/hybrid) [centroid]:` Enter, `Log format (text/json) [text]:` Enter. The next prompt is `Enable AI query expansion (HyDE + RAG Fusion)? [y/n]:` (skipped with `--enable-hyde` or `--enable-rag-fusion`), then the graph step (inside the same gate), then the description step, then the summary and `Proceed? [y/n]:`.
- Reading the written config while the wizard waits at `Proceed? [y/n]:` (the file is written before that prompt): in a second terminal that has the same `export ARCHON_SEARCH_DATA_DIR=...` (without it `"$ARCHON_SEARCH_DATA_DIR/archon-search.toml"` expands to `/archon-search.toml`, which `config set` would then target), `cat "$ARCHON_SEARCH_DATA_DIR/archon-search.toml"` (or `.venv/bin/archon-search config show --config <file>`).
