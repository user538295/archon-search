## Context

Collection descriptions were produced by one hard-wired call to the `claude-agent-sdk` package in `description_generator.py`. The package was a core dependency, so every installation carried it; the feature worked only with `ANTHROPIC_API_KEY`; every failure was logged at DEBUG; nothing in `/status`, `/ready` or the wizard said that it did not work; and an operator could not set a description by hand, because the collection patch route accepts only the embedding model and the default TTL. Meanwhile HyDE, RAG Fusion and graph enrichment each carried their own provider code: five query-expansion adapters under `archon_search/providers/`, four enrichment clients and a factory under `archon_search/enrichment/`, two protocols with opposite failure rules (query expansion never raises, enrichment raises), and a different place for each feature's dependency guard. A local model (`ollama`, `llama_cpp`) could serve three of the four features but not descriptions, and no feature sized its prompt to the model's context window.

The collection-descriptions brief set three product decisions that shape this ADR: the feature mirrors HyDE (own wizard question, own provider, model and host); it is **off by default** (an operator with only an Anthropic key stops getting descriptions until they opt in, announced in `BREAKING.md`); and prompts are sized ahead of time to the window, with no truncation safety net after the call.

## Decision

**All four LLM features (HyDE, RAG Fusion, graph enrichment, collection descriptions) call one shared, consumer-owned LLM client, one instance per feature, built from that feature's own section. Descriptions become a provider-based feature on that client, off by default.** The client lives in `archon_search/llm_client/` (stdlib-only protocol; wrappers per provider); composition is in `archon_search/server/llm_composition.py`.

### The shared client

1. **One interface, five providers.** `LlmClient.call(request)` is stateless (one user message, no history) and every failure is raised as `LlmCallFailure` (a timeout as `LlmCallTimeout`, a model that rejects `think` as `LlmThinkingNotSupported`); a wrapper never returns a fallback. The caller owns the fallback (`hyde_applied: false`, the single query, an unsummarised community, description status `failed`) and logs one WARNING per process through `warn_once`. This replaces the never-raise versus raise split of C6. Providers: `anthropic`, `openai` and `ollama` through their own SDKs (extras `hyde`, `openai-provider`, `ollama`; imported lazily), `llama_cpp` over `httpx` (core), `claude_cli` through the `claude -p` subprocess.
2. **Each feature keeps its own provider, model, host and context setting.** `[description]` mirrors `[hyde]` (`timeout_seconds` defaults to 30 instead of 10; generations are capped by a process-wide concurrency limit instead of a per-minute limit).
3. **`claude_cli` is locked down and gets graph.** The prompt goes on standard input (never the argument list, which shows in the process list and hits the size limit), with tools disabled, no session saved, no slash commands or MCP servers, `--max-turns 1`, `--safe-mode`, an empty temporary working directory, an allowlisted environment (no `CLAUDECODE` and no API key; the dev-container proxy token passes through), and the child is killed on timeout and on cancellation. Graph enrichment gains `claude_cli` (reversing C6's deferral) with `extraction_rate_limit_rpm` applied to it as to `anthropic`; HyDE and RAG Fusion on `claude_cli` stay unthrottled.
4. **Per-feature context windows.** Cloud providers get no setting and no trimming. `llama_cpp` reads its window from `GET /props` and counts exactly with `/tokenize`; a failed probe assumes 4096 and warns once per server. `ollama` takes `ollama_context_tokens`, sends it as `num_ctx`, and estimates with a gpt2-based token counter (`openai-community/gpt2`, a pinned revision, loaded lazily) plus a 20% margin on top of the template and a reserved answer of 1024 tokens; unset means 4096 assumed, no `num_ctx` sent and one startup WARNING per feature (existing HyDE, RAG Fusion and graph users on Ollama see it after upgrade); a configured value above the model's own maximum, read from Ollama at startup, warns too. Graph-summary and description prompts are sized ahead to the window (HyDE and RAG Fusion keep their 2000-character query cut and only gain `num_ctx`); there is no truncation detection after the call. The estimate was first measured on English, Python code and a small Hungarian sample (real tokens over gpt2 tokens at most 1.02) and then, in the manual run of checklist T-2, on seven text classes (adding Chinese, Japanese, emoji and digit-heavy text) against four real Ollama models; that run added the digit and emoji surcharges described under Negative / Tradeoffs. `llama_cpp` counts the template through the server's own chat template (`POST /apply-template`, then `/tokenize`), because the same run showed the framing (29 tokens on Qwen2.5) eating the reserved answer space when only the bare text was counted.
5. **Package guards by feature.** HyDE and RAG Fusion keep refusing to start without their provider package (`_check_provider_deps`: `anthropic` when the feature is enabled, `openai` and `ollama` whenever that provider is configured), because they are an explicit opt-in on the query path. Graph enrichment and descriptions never refuse: a missing or broken package for `anthropic`, `openai` or `ollama` is one WARNING naming the package, with the install command only when it is missing (`server/provider_dependency.py`), graph runs without summaries (`graph.enabled` stays true), and descriptions fail visibly. `llama_cpp` and `claude_cli` are never guarded by package. A package that is lost after boot is a failed call for HyDE and RAG Fusion too. Boot is never blocked by an optional LLM provider.
6. **Removed.** `archon_search/providers/`, `archon_search/enrichment/`, `query_expansion_protocol.py`, `graph_enrichment_protocol.py`, `HyDEDependencyError`, `RAGFusionDependencyError`, `EnrichmentClientFactory`, `_build_query_expansion_provider` and the three `tsp_contract` seams that described them; every caller moved (clean cutover, no shims).

### Collection descriptions

7. **Off by default.** `[description] enabled = false` unless set. Nothing is sent to any provider while it is off. With `ANTHROPIC_API_KEY` set and no `[description]` section the server logs one INFO that says so and how to enable it. The wizard asks its own question (`y` or `n`, closed stdin counts as no, with a privacy banner: `anthropic`, `openai` and `claude_cli` send excerpts off the machine).
8. **State on the collection.** `description_source` (`generated` or `manual`) and `description_status` (`ok` or `failed`; `pending` exists only in memory and is overlaid on reads) are nullable columns added by startup migration, with no `STORE_SCHEMA_VERSION` bump. A description from before the feature reads `generated` / `ok`. The two columns, and the missing `default_ttl_seconds` migration, run at every start (see item 14).
9. **Manual wins.** A description set by hand through `PUT /collections/{name}/description`, the MCP tool `set_collection_description` or the CLI is source `manual`, status `ok`, and generation never overwrites it; `DELETE`, `clear_collection_description` or the CLI clear it, reset the baseline and start nothing. Authorization is "the collection exists in the caller's namespace" (not admin; a config-only collection is `404`, unlike `GET`).
10. **Lifecycle.** One lifecycle service (`description_lifecycle.py`) owns generation: kinds `describe`, `ingest` and `backfill`; single-flight per collection; one generation in the process at a time; a prioritised queue bounded at 64 (describe, then ingest, then backfill); the existing 20% regeneration rule is unchanged; every task is cancelled at shutdown. An ingest returns without waiting for the model. `POST /collections/{name}/describe` starts an on-demand generation as a `description` job (`202`; `409` for a manual description or when descriptions are not configured), `collection describe` and `describe --all` are the CLI entry points. A startup backfill (`backfill_on_startup`, default off, `description_backfill.py`) fills collections that have no description, one at a time across every namespace, after the startup sync; it is skipped while the sync is suppressed. The startup probe runs whenever descriptions are enabled, independent of the backfill and of the sync state (it sends no prompt and no document text, so "no provider is called" under a suppressed sync means no generation call). Its verdict is reported in `/status` (`description` block) and in the log; description health never feeds `/ready` or `provider_warnings`.
11. **Output rules.** One line of at most 600 characters, cleaned (thinking tags, control characters), one automatic retry that restates the rule, then trimmed to the last full sentence; nothing usable is status `failed` and the old description is kept. `[description].think` (`default`, `true`, `false`) reaches every `ollama` and `llama_cpp` call, retry included; the other providers ignore it, with a startup WARNING; a generous answer ceiling lets reasoning models answer. Manual text is validated, never trimmed.
12. **Sample and privacy.** The sample is drawn deterministically across the whole collection: open chunks (no ACL) ordered by `chunk_id`, picked evenly spaced, the largest number up to `max_sample_chunks` that fits the input budget. `include_restricted_chunks = true` (local providers) is the operator's explicit switch and warns at startup. Excerpt and description text never reach logs or telemetry (C4/C5/ADR 05 stand). Generated text is untrusted data: the router collapses whitespace and escapes `<` and `>` in every description before it enters the `<search_collections>` prompt block, and the MCP schemas label the field as data derived from document content.
13. **One write path.** `SearchStore.write_description` is the only writer of description changes (the recompute's legacy repair, described in the ADR 07 bullet above, is the one exception): it takes the collection lock, re-reads the row, applies a guard (a manual set always wins; a stale generated write is refused) and writes the text, source, status and the routing vector (`description_embedding`) in one step; the vector is computed outside the lock with the collection's own embedder from the embedder cache (bounded wait), and a failed embedding keeps the text and removes the old vector. This is the correction to ADR 07: the vector now follows every change (generate, manual set, clear, import).
14. **Migrations and export.** `_run_startup_migrations` now also runs `migrate_default_ttl_seconds` (every metadata write names that column, and a store without it failed the write inside LanceDB), plus the description columns; this reverses the earlier practice that version-1 migrations run only through `POST /collections/{name}/migrate` (the route stays valid and is a no-op for that spec). The export manifest is version 2 and carries `description_source` next to a non-empty `description`; import restores a description through the same write operation (`manual` stays `manual`, a sourceless description becomes `generated`, status `ok`), normalises it to one line of at most 600 characters, and refuses version 1 archives unless `ignore_schema_version`.
15. **`claude-agent-sdk` is removed** from `pyproject.toml` and `uv.lock`, with its `CLAUDECODE` environment mutation and process-wide lock; a test proves the package is absent from the dependency list, the lock and the lightweight CLI start.

## Consequences

### Positive

- A fully local setup (`ollama` or `llama_cpp`) produces descriptions with no Anthropic key and without `claude-agent-sdk`, which no installation carries any more.
- One place implements providers, failure logging, rate limiting and window handling; adding a provider or a feature means one wrapper or one consumer, and the provider registry sync test guards the lists.
- An enabled but unusable provider is visible at startup, in `/status` (`reachable` is the startup probe's verdict and is not refreshed; a later outage shows in the last attempt) and on the collection (`failed`), instead of at DEBUG.
- A manual description is possible, protected and exported; the routing vector no longer goes stale.
- Prompts fit the model's window by construction, which keeps small local models usable.

### Negative / Tradeoffs

- Off by default: an operator who relied on automatic descriptions with an Anthropic key gets none until they opt in (`BREAKING.md`).
- Graph on `openai` or `ollama` now needs those packages, and every existing Ollama user sees a new WARNING until `ollama_context_tokens` is set; two Ollama features that share a model but use different windows make Ollama reload the model on each switch.
- Every pre-upgrade backup is a version 1 archive and needs `ignore_schema_version` to restore (the embedding-model check still applies); a bypassed restore loses nothing but carries no description source.
- No truncation safety net: if the gpt2 estimate is exceeded on text it was not measured on, Ollama would describe a prompt that lost its tail and the result would be stored as `ok`; an unset `ollama_context_tokens` cannot protect a server whose real window is below 4096.
- The estimate is gpt2 plus two surcharges, found by measuring real Ollama models (llama3.1 8b, qwen2.5 1.5b, gemma3 1b, tinyllama; manual checklist T-2): a plain gpt2 count stayed within the 20% margin on prose (at most 1.198x, tinyllama on dense Wikipedia text), code, Hungarian, Cyrillic, Korean, Arabic, Hindi, Chinese, Japanese, base64 and URLs, but digit-heavy text cost 1.68x on per-digit tokenizers (qwen, gemma, llama 2), single digits separated by spaces 1.9x, two-digit numbers up to 2.8x and emoji 1.55x on byte-fallback tokenizers (llama 2 sentencepiece). The counter therefore counts every ASCII digit as one token plus one per digit run, and every character outside the Basic Multilingual Plane as four, and the real count of every one of the 19 measured classes stays within 1.2x that estimate (worst 1.15: digit-free English prose on tinyllama; BMP symbols and keycap or ZWJ emoji sequences 1.14). The surcharges make the estimate pessimistic for digit- and emoji-heavy text (smaller prompts than necessary) and leave a tokenizer family that was not measured unproven.
- `llama_cpp` sizing needs `POST /apply-template` (present in llama-server 0.7.0, the version measured) as well as `/tokenize`: a server without it fails the sizing call, so graph summaries and descriptions fail on it with a reason naming HTTP 404. The framing is measured for a plain user message; a template that changes with `think` is not accounted for, because `/apply-template` is called without the `chat_template_kwargs` of the call.
- The chat framing Ollama adds (9 to 33 tokens on the four models measured; Qwen's default system prompt is 29) is not counted for `ollama`: in the at-budget calls of the manual run the prompt plus the 1024-token reserve stayed at least 387 tokens inside the window, which covers it, but nothing guarantees that for a model with a long built-in system prompt.
- A client that aborts `POST /search` or `POST /explain` cancels the request (`CancelOnDisconnectMiddleware`, outermost, reads the connection only after the application has read the body): the HyDE, RAG Fusion and graph calls of an abandoned search stop and a `claude` child is killed, found when the real run showed the child surviving to its natural end. The MCP tools run the same calls and are not covered.
- `pending` and the last attempt are in memory only and are lost at restart; backfill skips collections whose stored status is `failed`, so only the next qualifying ingest or `collection describe` retries them.
- Rolling back to the previous server is untested (it writes metadata rows without the two new keys); a legacy description may stay vectorless (centroid fallback in hybrid routing); `timeout_seconds` (30 per attempt) can be too short for a cold local model, and a timeout is a failure, not a retry.
- Cloud providers receive up to `max_sample_chunks` open excerpts (and a retry sends them twice); `claude_cli` was checked against `claude` 2.1.308 on macOS only (`--max-turns` is accepted though not listed in `--help`).
- Any key whose namespace owns a collection can force paid generations with `collection describe`; calls are serial and single-flight but not rate limited per key.
- A semantically misleading description built from untrusted chunks can still bias routing and mislead an MCP agent that obeys it; escaping prevents only structural injection.

## Alternatives Considered

- **Keep the SDK and add a provider switch around it.** Leaves four separate provider stacks and a core dependency used by one feature.
- **A no-LLM description (top terms, file types).** Dropped by the product owner for now.
- **Truncate and detect after the call.** No reliable truncation signal across the five providers; sizing ahead is deterministic and testable.
- **A generic OpenAI-compatible provider** instead of `llama_cpp`, `ollama` and `openai`: rejected in C6 for the same reasons.
- **A version bump and per-collection migration for the new columns.** Rejected: nullable columns follow the startup-migration practice already used for `community_rebuild_job_id` and `metadata_reindex_job_id`.
- **Per-collection provider overrides, multilingual or customised prompts, a describe MCP tool, an `--enable-description` install flag:** out of scope.
