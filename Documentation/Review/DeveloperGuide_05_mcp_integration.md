# Review: DeveloperGuide/05_mcp_integration.md

## Summary

The nine tool names, argument shapes, return shapes (`SearchResult` fields, envelope for `search`, list-shape for `search_with_context`, `{"deleted": int}` for `delete_document`, `centroid`-omitted-vs-included for the two list/get meta tools, `not_found` for missing collection, in-band `{"error","code"}` errors), and `/health` exemption are all consistent with `archon_search/server/mcp.py`. The big finding is structural: **the FastMCP HTTP app (`create_mcp_http_app`) is defined but never wired into the runtime.** `archon_search/server/app.py:create_app` only mounts FastAPI routers; `run_server` builds the FastAPI app and starts uvicorn with no mention of `/mcp` and no call to `create_mcp_http_app`. A grep over `archon_search/**` shows the function has zero callers outside `tests/server/test_mcp_auth.py`. That invalidates several framing sentences (same FastAPI process, "/mcp" reachable, registration/curl examples will not work against the shipped server). Several smaller line-number citations are also off.

## Inaccuracies (numbered)

1. Line 8 — "Both are served by the same FastAPI process" and "The MCP transport is `FastMCP`'s streamable HTTP (`fastmcp_app.streamable_http_app()`); the auth wrapper is the same `APIKeyMiddleware` used for REST." The Starlette MCP app is built by `create_mcp_http_app` but is **not mounted** by `archon_search/server/app.py:create_app` nor started by `run_server`. Only `create_app` (FastAPI) is run. The doc presents `/mcp` as a live endpoint of the shipped server; in the current code it is not.
2. Line 8 — Citation `archon_search/server/mcp.py:248-252` for the auth wrapper. The relevant lines are `mcp.py:248-251` (`fastmcp_app = create_app(...)`, `streamable_http_app()`, `load_or_generate_key()`, `add_middleware(APIKeyMiddleware, ...)`). The `return` is at `:252`. Minor, but the cited range is one line off and includes the bare `return`.
3. Line 12 — "`GET /health` on the MCP app is exempt from auth (`mcp.py:230`)". The `/health` route is registered on the FastMCP app at `mcp.py:230` via `@app.custom_route`, but the **exemption from `APIKeyMiddleware` is not defined in `mcp.py`** — it comes from `_EXEMPT_PATHS` in `archon_search/server/middleware_auth.py:16` (`{"/health", "/docs", "/openapi.json", "/redoc"}`). The doc's citation points to the route declaration, not the exemption mechanism, and the wording elides that the exemption is shared across REST and MCP middleware (same `APIKeyMiddleware`, same constant).
4. Line 17 heading "The nine tools" and line 19 "Verified against `archon_search/server/mcp.py`. The `collection` argument defaults to the server's `default_collection` when omitted." Accurate as a description of the code path (`collection or default_collection`), but the doc's claim further down (line 103) that this is "the first registered collection in config" is **not verifiable from config**: `SearchConfig` (config.py) has no `default_collection` field. `default_collection` is a parameter to `create_app(pipeline, default_collection, ...)` / `create_mcp_http_app(pipeline, default_collection, ...)` with no caller in the runtime, so the actual default is whatever the (missing) caller passes. The "first registered collection" claim has no source-code basis.
5. Line 26 — `ingest_directory` "`list[IngestResult]`". The tool returns `list[dict[str, Any]]` built from `[asdict(r) for r in results]` (`mcp.py:158`), but on exception it returns an `McpErrorResponse` dict, not a list (`mcp.py:161`). The error path is not reflected in the return-column. (Same caveat applies to every other tool row that lists only the happy-path return; the doc's section after the table does call this out generically, but the table itself is misleading.)
6. Line 27 — `list_collections` "`list[CollectionMeta]` with the `centroid` field omitted". Code uses `d.pop("centroid", None)` on each dict (`mcp.py:171`), so it returns `list[dict]`, not typed `CollectionMeta`. Pedantic given the table is informal, but the contrast with row 28 ("full `CollectionMeta`") implies a stronger typing guarantee than exists — MCP returns plain dicts (the same point the doc itself makes at line 14, "Responses are dicts, not validated").
7. Line 29 — `get_collection_meta` error shape `{"error": "Collection 'X' not found", "code": "not_found"}`. Code uses `name!r` in the format string (`mcp.py:194`), so the rendered error is `Collection 'X' not found` only when the name contains no special quoting; with double-quoted input it could render `Collection "X" not found`. Minor, but the doc's example is one of two possible renderings.
8. Line 33 — "Each `SearchResult` dict has the shape `{doc_id, chunk_id, text, score, source_path}`". The dataclass at `archon_search/_types.py:25` has six fields: `doc_id, chunk_id, text, score, source_path, acl`. MCP returns `asdict(r)` (`mcp.py:59`, `:102-104`) so `acl` **is** present in the MCP output (unlike REST `SearchResultSchema`, which strips it at `routes_search.py:39-54`). The doc claims MCP and REST shapes match; they do not.
9. Line 33 — Citation `routes_search.py:39` for the REST schema. Correct line for the class declaration. The doc's adjacent claim that MCP "matches the REST `SearchResultSchema`" is contradicted by #8.
10. Line 37 — "`search` over MCP returns the **same** envelope as REST (`{results, acl_filtered}`) — this is the post-`BREAKING.md` shape; the old bare-list response is gone." Envelope shape matches at the top level, but per #8 the per-result dicts differ (MCP has `acl`, REST does not). Calling this "the same envelope" needs a per-result qualifier.
11. Line 38 — "`search_with_context` exists **only** on MCP. There is no REST equivalent." Verified: `grep -rn search_with_context archon_search/server/routes_*.py` returns no hits. Accurate. (Listed for transparency; not an inaccuracy.)
12. Line 39 — "Ingest is **synchronous** on MCP". Accurate vs `mcp.py:131`/`:152` (the tool `await`s `pipeline.ingest_*` and returns the result). "REST's `POST /ingest` is async (returns a job)" — verified at `routes_jobs.py:91` (`status_code=202, response_model=JobResponse`). Accurate.
13. Line 40 — "`list_documents` and `delete_document` are **MCP-only**." Verified: no `/documents` routes are registered in the FastAPI routers (`grep` for `list_documents`/`delete_document` hits only `mcp.py`). Accurate.
14. Lines 42-58 — "Registering with Claude Code" / example JSON pointing at `http://127.0.0.1:8765/mcp`. Because the MCP app is not mounted (see #1), this configuration **will not work against the shipped server**. The example is aspirational, not operational. The doc presents it as a working recipe.
15. Lines 87-98 — `curl` example posting to `/mcp` with `tools/list`. Same problem as #14: the `/mcp` endpoint is not exposed by `run_server`. The "200 response with nine tools" success criterion cannot be observed against the current runtime.
16. Line 104 — "`mcp.py:48-58`, `:88-99`". The first range is right for the `search` telemetry-enqueue block (lines 47-58 actually, off-by-one start). The second range covers the `search_with_context` enqueue block (88-99 matches `try`/`writer.enqueue`/`except`). Acceptable, but #1 (`:48-58` starts at the docstring/`start = monotonic()` rather than at the `if writer is not None`) is slightly off.
17. Line 103 — "Default collection. Every tool that takes `collection?` falls back to `default_collection` (the first registered collection in config)." The "first registered collection in config" sub-claim is unsupported — see #4. `SearchConfig.namespaces` exists (`config.py:54`) but there is no field named `default_collection` and no logic in `config.py` that elevates the first namespace to a default. Whatever value `default_collection` takes comes from the caller of `create_app`/`create_mcp_http_app`, and that caller does not currently exist in the runtime.
18. Line 13 — "Adding or renaming a tool requires a `BREAKING.md` entry." Project-policy claim, not directly verifiable from `mcp.py`. `BREAKING.md` exists in the repo. The CLAUDE.md says breaking REST/MCP changes go in `BREAKING.md`. Consistent with policy; flagged only because the doc states it as a hard rule without citing the policy source.

## Verified claims

- Nine `@app.tool()` decorators in `create_app` at `mcp.py`: `search` (38), `search_with_context` (76), `ingest_file` (124), `ingest_directory` (139), `list_collections` (163), `get_collections_meta` (178), `get_collection_meta` (188), `list_documents` (200), `delete_document` (215). Count, names, and order all match the doc's table.
- Argument names, types, and defaults for each tool match the doc:
  - `search(query, collection=None)` (mcp.py:39-42)
  - `search_with_context(query, collection=None, context_window=1)` (mcp.py:77-80)
  - `ingest_file(path, collection=None)` (mcp.py:125-127)
  - `ingest_directory(path, glob_pattern="**/*", collection=None, ctx=None)` (mcp.py:140-144)
  - `list_collections()` (mcp.py:164)
  - `get_collections_meta()` (mcp.py:179)
  - `get_collection_meta(name)` (mcp.py:189)
  - `list_documents(collection=None, limit=100)` (mcp.py:201-203)
  - `delete_document(doc_id, collection=None)` (mcp.py:216-218)
- `search` success return is `{"results": [asdict(r) ...], "acl_filtered": result_obj.acl_filtered}` (mcp.py:59) — envelope shape matches doc.
- `delete_document` success return is `{"deleted": count}` (mcp.py:225) — matches doc.
- `get_collection_meta` returns `McpErrorResponse(error=f"Collection {name!r} not found", code="not_found")` when meta is None (mcp.py:194) — matches doc's error code.
- All tools return `McpErrorResponse(error=str(exc), code="internal_error")` on exception — matches doc's "errors are in-band" claim and `06_error_handling.md` referenced shape.
- `list_collections` strips the `centroid` field (`d.pop("centroid", None)`) at mcp.py:171; `get_collections_meta` returns full `asdict(r)` without stripping at mcp.py:183 — matches the centroid-omitted/included distinction in the table.
- `ingest_directory` reports progress via `ctx.report_progress(done, total)` (mcp.py:150) — matches the doc's operational note.
- Telemetry is only enqueued by `search` and `search_with_context`, not by ingest/list/delete tools — matches doc's "Telemetry side effects" scope.
- Auth middleware: `APIKeyMiddleware` at `archon_search/server/middleware_auth.py`, exempt paths `{/health, /docs, /openapi.json, /redoc}` (line 16). Both REST and MCP wrappers add this middleware — matches "same auth as REST" claim.
- `SearchResult` dataclass at `archon_search/_types.py:25` has fields `doc_id, chunk_id, text, score, source_path, acl` (six fields, not five — see Inaccuracy #8).
