# Component Catalog and Layer Breakdown

This is the module-level map of `archon_search/`. One row per module, grouped by layer. Use it to find where a change belongs before reading code. Cross-cutting flows are in [100_system_architecture_overview.md](100_system_architecture_overview.md); the wire surface is in [600_api_reference_or_public_interface.md](600_api_reference_or_public_interface.md).

## Principles

1. **One module, one layer.** A module that touches two layers (e.g. parser code in a route handler) is a smell — escalate before merging.
2. **Layers depend downward only.** Server depends on Query/Ingest; Query/Ingest never imports Server.
3. **Names mirror responsibilities.** `routes_*.py` are HTTP edges; `*_meta.py` are metadata models; `_types.py` is the dataclass spine.
4. **Underscored modules are internal.** `_types.py`, `_diagnostics.py`, `_helpers.py`, `_durable_io.py` are not part of the public import surface.
5. **No reaching across siblings.** Pipeline stages talk to each other only through `SearchPipeline`; route modules talk to each other only through `app.state`. (#Unverified — `routes_collections.py` currently imports `IngestRequest` and `_default_ingest_task` from `routes_jobs.py` at module level, and `routes_status.py` imports the `_all_collection_paths` helper from `routes_collections.py` at module level (also reused function-locally by `mcp.py`); these are type/helper imports rather than runtime state sharing, but they bend the rule.)

## Layer summary

| Layer | What it owns |
|---|---|
| Ingest | Parsing, chunking, ACL resolution from disk |
| Index | Embeddings, vector + FTS store, collection metadata |
| Query | Hybrid search, reranking, search-with-context, ACL filtering |
| Routing | Multi-collection selection via centroid pre-ranking |
| Metadata | Per-collection descriptions and centroids |
| Server | FastAPI app, MCP app, middleware, route modules, schemas |
| CLI | Click entry points and subcommands |
| Platform | OS service install/uninstall (launchd, systemd, Windows) |
| Telemetry | Opt-in JSONL writer/reader/pruner |
| Jobs | Async job lifecycle for long-running ingest/reindex |
| Eval | Deterministic backends + harness for the regression gate |
| Cross-cutting | Config, constants, types, progress, key manager |

## Ingest

| Module | Purpose | Key public symbols |
|---|---|---|
| `archon_search/parser.py` | Extract text from files, routing by extension: plain text and code via `Path.read_text`, HTML via trafilatura, PDF and images (OCR) via docling, Office formats (`.docx`, `.pptx`, `.xlsx`, `.xls`, `.rtf`, `.epub`, `.eml`, `.msg`) via markitdown. Raises `ParseError` on unrecoverable failure: its `str()` names the path and the raw cause and goes to the log only, while `ParseError.detail` is the wire-safe text — `PARSE_FAILED_DETAIL` unless the raise site curated its own (the lost-worker and missing-markitdown texts) — that `pipeline.ingest_file` returns as `Failed to parse <path>: <detail>` (`PARSE_FAILED_TEMPLATE`, also `ParseError`'s own log-only message with the raw cause) under `code` `_types.PARSE_ERROR_CODE` (`parse_error`). **The docling formats (PDF + images) run in a child process, not in the server process**: `DocumentParser` owns a lazily-created single-worker `ProcessPoolExecutor` (`spawn` context, `max_tasks_per_child=[ingest].max_tasks_per_child`, default 25) and the worker exits after that many files — process exit is the only complete reclaim of the native memory docling/RapidOCR/onnxruntime retain per conversion. The converter is built with a concrete `RapidOcrOptions(backend="onnxruntime", scale=1.0)` rather than docling's default `scale=3.0` — this override is **image-only** (`InputFormat.IMAGE`); for images `scale` multiplies the native bitmap, so `1.0` is a no-op, whereas for a PDF it is a 72-DPI render multiplier with no source bitmap to preserve, so `InputFormat.PDF` is deliberately absent from `format_options` and PDFs keep docling's own default scale. The worker entry point `_docling_to_markdown` returns `(ok, payload)` and never raises across the process boundary; the caller rebuilds a `ParseError` whose `cause` carries the original exception's type and message (not the original object — unpickling it would import docling back into the caller). A `BrokenProcessPool` drops the pool so the next file gets a fresh worker. Pool creation is lazy, so a text-only caller — and the server's startup path — never spawns one. | `DocumentParser`, `ParseError`, `PARSE_FAILED_DETAIL`, `PARSE_FAILED_TEMPLATE`, `PARSE_WORKER_LOST_DETAIL`, `MARKITDOWN_MISSING_DETAIL` |

| `archon_search/language_detector.py` | **C2** — Per-document language detection using the fasttext `lid.176.ftz` model. | `archon_search/embedder.py` | Dense-embedding façade with a Protocol backend. `UnsupportedModelEmbedder` is the cold backend `server/app.py`'s `_embedder_backend` substitutes for a configured name outside the registry: every `encode` raises `UnsupportedModelError`, so the server starts and reports `checks.models: "fail"` (S750). `ModelEmbedder(model_name, device)` is the PyTorch backend: it resolves the model's spec from `model_specs.py` at construction (a name outside the registry raises `UnsupportedModelError`), and builds the encoder lazily, on the first `encode` call — `model_store.ensure_model` fetches the pinned snapshot, `torch_runtime.resolve_device` maps `[database].device` to a torch device, and `text_batching.plan_batches` splits the texts into token-budget batches. A failed build is not latched; the next call retries. `make_embedder(model_name, device="auto")` wraps it. **S184**: `Embedder.warmup()` forces that build off the request path — a no-op when `backend.is_warm`, otherwise one throwaway `embed(["warmup"])`, which also caches `embedding_dim`. **S290**: the build is **single-flight** through a `warmup_coordinator.WarmupCoordinator` (shared with `Reranker`): one shared task runs it and every caller only `await asyncio.shield(...)`s that task, so the bounded `warmup_for_search` wait cancels nothing but its own wait. Without that, each cold request started another `to_thread` encode that queued behind the one model build on `ModelEmbedder._lock` — a pinned executor thread per concurrent request — and the cancelled attempt never reached the `_embedding_dim` assignment. The coordinator's task belongs to one event loop and is replaced when the running loop changes. A settled task is never re-awaited, so a failed build is retried by the next caller rather than latched (S283); a build that fails after every waiter has gone is logged at WARNING with its traceback. A build that outruns `WARMUP_TIMEOUT_SECONDS` (300 s, one constant in `warmup_coordinator.py`) raises **`EmbedderWarmupTimeout`** (a subclass of `WarmupTimeout`) — a plain `Exception`, deliberately *not* an `asyncio.TimeoutError`, so "the build blew its own ceiling" stays distinguishable from "this caller gave up waiting" (which since 3.11 also covers a socket `ETIMEDOUT` from a model download, so the conversion fires only when the ceiling actually cancelled the build). | `Embedder`, `EmbedderBackend`, `EmbedderWarmupTimeout`, `ModelEmbedder`, `make_embedder` |
| `archon_search/embedder_cache.py` | LRU cache for `Embedder` instances keyed by model name. Avoids reloading the same model weights when multiple collections use different models in the same process. Capacity is controlled by `[database].embedder_cache_size` (default 3); the lifespan's warm-up task populates the cache at startup on every configuration — with `[database].embedding_model` alone by default, or, when `[database].eager_load_embedders = true`, that model plus every non-empty per-collection `active_embedding_model`. A model whose start-up warm-up `embed()` fails is evicted only when its backend never loaded (`is_warm` is False), so `cached_models()` never reports a cold model as preloaded; an embedder that did load and then failed inference is kept, because the load cost is already paid. **S632** — `preload(model_names)` returns the names whose load or warm-up `embed()` failed, in `model_names` order (`[]` when every model warmed): a deliberate command-with-outcome, because cache state cannot tell a model the LRU evicted after warming from one that failed. `cold_models(model_names)` is the side-effect-free state probe a timed-out warm-up (whose `preload` never returned) uses instead: the names in `model_names`, in order, that are not cached or are cached with no backend built (`is_warm` False); it loads nothing and leaves the LRU order untouched. `[database].device` (the torch device setting) is forwarded to every cached `make_embedder` call — searches embed through this cache, not through the global `app.state.embedder`, so without it the configured accelerator would never be used on the search path. Evicts the least-recently-used model when the cache is full — except the **pinned default embedder**: the lifespan seeds the cache with the pipeline's own embedder (one copy of the default model, not a second load), that entry is never evicted and does not count towards `embedder_cache_size`. When an eviction drops a warm embedder, `torch_runtime.release_model_memory` runs off the event loop (a failure is logged at WARNING with its traceback) so the weights and the accelerator's driver cache are returned; an in-flight request that still holds the evicted embedder keeps it alive until it finishes. | `archon_search/store.py` | LanceDB-backed store: vector ANN + FTS, RRF fusion in `hybrid_search_with_trace`, document/chunk lifecycle, namespace + ACL migrations, collection metadata persistence. `hybrid_search_with_trace` is a thin instance-method delegate to the module-level `_hybrid_search_with_trace`, which returns `list[ScoredSearchCandidate]` with full score provenance — used by `SearchPipeline.explain` and by every production search path. **S290**: its `query_vector` is `list[float] | None` — `None` skips the vector leg entirely and fuses the FTS leg alone, the degraded ranking a search falls back to when the embedder is still cold.
