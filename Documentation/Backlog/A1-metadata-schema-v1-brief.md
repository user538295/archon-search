# Feature Brief: Metadata Schema v1 (A1 — item 3, minimum slice)

## Problem
The LanceDB chunk schema and the `ChunkRecord` dataclass already declare per-chunk metadata fields (`file_type`, `language`, `updated_at`, `ingested_by`, `custom_score`, `acl`, free-form `metadata` JSON), but the **ingest pipeline does not populate most of them** (file_type is never set by `DocumentChunker.chunk()`; `updated_at` defaults to empty and falls back to `indexed_at` in `store.py`; `ingested_by` is hard-coded to `"archon-search-cli"` regardless of source) and the **search response surface omits all of them** (`SearchResult` carries only `doc_id, chunk_id, text, score, source_path, acl`; `SearchResultSchema` in `routes_search.py` mirrors that minimal set; MCP `asdict()` therefore exposes the same minimal set). As a result, A2 (metadata filters) and C1 (per-collection embedding model) cannot be built without first deciding which fields are real, who populates them at which call site, what partition (system / filterable / ranking / audit) they belong to, and how they surface in the public response contract.

## Goal
A1 ships a typed, documented, end-to-end metadata schema slice — minimum fields needed to unblock A2 and C1 — with extraction wired from parser through chunker into the store, fields surfaced in REST + MCP search responses (including `SearchResult` dataclass growth), a partition map annotated **on the code only** (with the persistence doc referencing the code as source of truth), and an opt-in CLI to backfill existing collections. Success is observable as: (a) a fresh ingest of `foo.md` produces a chunk row with `file_type == "md"`, non-empty `updated_at`, and `ingested_by` reflecting the call site; (b) the `/search` JSON response includes those fields; (c) the MCP `search` tool returns the same fields; (d) `archon-search collection reindex-metadata <name>` populates the same fields on a pre-A1 collection; (e) the eval harness still passes; (f) the 85% coverage gate holds on the default pytest run.

## Users & Context
- **Developers integrating archon-search** (REST/MCP clients) who want filterable, predictable per-chunk metadata in search results.
- **Operators of existing deployments** who have already-ingested corpora and need a non-destructive path to populate new fields.
- **Contributors to the codebase** (current and future) who need a single canonical reference for which metadata fields exist, what they're for, and which partition they belong to.

## Core Flow
1. **Ingest path**: `DocumentParser` resolves a file and lowercases its suffix (already does — `parser.py:55`). The suffix-without-dot is threaded as `file_type` through `DocumentChunker.chunk()` (currently doesn't accept it) into the `ChunkRecord` objects, alongside `updated_at` (= file mtime as ISO 8601 from `path.stat().st_mtime`; falls back to `indexed_at` if `stat()` raises, e.g., stdin or vanished file) and `ingested_by` passed down by the caller. `SearchStore.ingest_chunks` then writes them as-is — the existing fallback `updated_at = updated_at or indexed_at` stays.
2. **Source-of-ingest plumbing**: each entry point sets `ingested_by` explicitly: CLI ingest → `"cli"`, REST `/ingest` and job ingest → `"http"` (the `X-Ingested-By` header still allows overriding; the legacy literal `"archon-search-cli"` is normalized to `"cli"` for backward compatibility; other unknown values are coerced to `"http"` with a WARNING log), watcher/sync re-ingest → `"watcher"`, `reindex-metadata` CLI → `"reindex"`. The hardcoded default `"archon-search-cli"` on `ChunkRecord` is removed in favor of a required parameter at the chunker call site; old rows in existing stores still carry the legacy `"archon-search-cli"` bytes on disk but are **normalized to `"cli"` at the read boundary in `SearchStore`** so the typed `Literal` never sees the legacy value (see Edge Cases for the migration story).
3. **Response surface**: `SearchResult` dataclass grows `file_type: str`, `indexed_at: str`, `updated_at: str`, `ingested_by: str`, and `metadata: dict[str, str]` (in addition to existing `doc_id, chunk_id, text, score, source_path, acl`). `SearchStore.hybrid_search` row-to-result mapping is extended to populate them. `SearchResultSchema` (Pydantic, REST) and the MCP `asdict()` payloads both gain the same fields automatically. For `search_with_context`, MCP currently returns raw `ChunkRecord` via `asdict()` — which includes `vector` (a large float list). A1 strips `vector` from context payloads before serialization to avoid a payload-size regression. `language` and `custom_score` remain on `ChunkRecord` but are **not** added to `SearchResult` — they are reserved at the storage layer only and do not appear in responses until C2 (language) / a future ranking feature (custom_score).
4. **Backfill**: `archon-search collection reindex-metadata <name>` walks existing chunks, re-derives `file_type` from `source_path` (lowercased suffix without dot; empty string if no extension), refreshes `updated_at` from current mtime (falls back to existing `indexed_at` if the file no longer exists — chunk is preserved, not deleted, and a per-file warning is logged), rewrites legacy `ingested_by == "archon-search-cli"` → `"reindex"`, and writes back. The command emits progress to stdout (`N/total` every K rows). Concurrency: reindex acquires the per-collection lock for the collection being rebuilt from a new `SearchStore._collection_locks: dict[str, asyncio.Lock]` map (lazily populated), serializing reindex vs. ingest of the same collection within a single process. Concurrent operations on **different** collections are unaffected. Cross-process safety remains out of scope and is documented.
5. **Partition map**: documented as docstring blocks / per-field comments on `ChunkRecord` in `_types.py`. `Documentation/Architecture/130_data_architecture_and_persistence.md` adds a one-paragraph pointer that says "see `_types.ChunkRecord` for the per-field partition map" — the doc does **not** re-state the partitions, preserving code-as-source-of-truth.
6. **Roadmap reconciliation**: `Documentation/Backlog/03_world_class_roadmap.md` is amended in the same PR to drop `language` from A2's listed filter dimensions and add a forward reference to C2.

## In Scope
- Threading file extension (lowercased, **without** the leading dot) through `parser.py` → `chunker.py` → `store.py`.
- Populating `updated_at` from `path.stat().st_mtime` at ingest, with fallback to `indexed_at` when `stat()` is unavailable.
- Populating `ingested_by` with the actual call-site identity (`cli` / `http` / `watcher` / `reindex`). Removing the unconditional `"archon-search-cli"` default in `_types.ChunkRecord` and in `store.py` write paths; existing REST `X-Ingested-By` header behavior is preserved (and `"archon-search-cli"` legacy value still accepted from clients).
- Growing `SearchResult` to include `file_type`, `indexed_at`, `updated_at`, `ingested_by`, `metadata`.
- Updating `SearchResultSchema` to mirror the new `SearchResult` fields **including the existing `acl` field that `from_result()` currently drops silently**. This closes an existing drift bug as part of the response-shape audit.
- Updating `SearchStore.hybrid_search`'s row-to-`SearchResult` mapping to parse the `metadata` JSON string into `dict[str, str]` via the existing `parse_metadata()` helper (currently only `_read_all_chunks` does this — `hybrid_search` constructs `SearchResult` directly from row dicts and would otherwise hand back a JSON string).
- Stripping `vector` from `search_with_context` MCP context payloads (`context_before` / `context_after`).
- `types.py` vs `_types.py`: audit only — no consolidation needed (planning has verified the two modules contain non-overlapping types).
- Verifying `custom_score` round-trips `None` correctly. (PyArrow's `pa.field` defaults `nullable=True` — the column is already nullable at the schema level. No schema migration needed; A1 only adds an explicit `nullable=True` keyword for readability and a round-trip integration test to pin behavior.)
- `archon-search collection reindex-metadata <name>` CLI command (opt-in backfill), with progress logging and a `--dry-run` flag.
- Introducing an in-process per-collection lock map on `SearchStore` (`self._collection_locks: dict[str, asyncio.Lock]`, lazily populated) to serialize reindex vs ingest of the **same** collection within one process. Ingest acquisitions use `asyncio.wait_for` with a configurable timeout (default 30s); on timeout, REST ingest returns HTTP 503 with a `Retry-After` header rather than hanging. Reindex never times out (it's the holder). Reindex acquires the per-collection lock for the collection it is rebuilding and holds it for the full duration; ingest into any **other** collection proceeds unblocked. The existing `sync.py:_collection_locks` (a separate, higher-layer construct) remains unchanged and continues to serialize watcher/sync writes to the same collection.
- Documenting the partition map (system / filterable / ranking / audit) as docstring blocks on `ChunkRecord` only; the persistence architecture doc gains a one-paragraph pointer to the code.
- `BREAKING.md` entry, scoped precisely: MCP `search`, `search_with_context`, `list_documents` response shapes gain new keys (true contract change for typed MCP clients that strict-validate); REST `/search` and `/search/context` responses gain new keys (additive, non-breaking for tolerant JSON consumers, but worth documenting).
- Amending `Documentation/Backlog/03_world_class_roadmap.md` to drop `language` from A2's filter dimensions and forward-reference C2.

## Out of Scope
- **Language detection** — deferred to C2. `language` stays on `ChunkRecord` (typed as `str | None`, default `None`) but is **not** added to `SearchResult` / `SearchResultSchema`. Reason: shipping a half-built field that leaks into responses is worse than not shipping it. Roadmap A2 amended to match.
- **`custom_score` population logic** — schema-reserved only. Column made nullable in A1 (one-line schema fix to match Python type); no population path.
- **Centroid incremental update (CON-4)** — deferred to B5.
- **Free-form `metadata` JSON validation / shape changes** — existing bounds (`_META_MAX_FIELDS`, `_META_MAX_KEY_LEN`, `_META_MAX_VAL_LEN`) unchanged.
- **`doc_id` hashing for telemetry privacy (SEC-2)** — deferred to D8.
- **Query-side filter wiring (LanceDB `where()` builders, REST filter params)** — A2's scope.
- **Auto-reindex on startup** — too disruptive; opt-in CLI only.
- **Cross-process locking for reindex** — out of scope; documented limitation.
- **MCP Pydantic-model wrapping (API-4 debt)** — stays deferred. A1 ships the **last** untyped MCP breaking change consciously; pulling C7 forward would balloon A1's scope. The `BREAKING.md` entry explicitly flags this as the last expected MCP shape break before C7.
- **Filter-result-quality signaling** (telling A2 callers "your filter dropped 80% of rows because they're pre-A1") — A2's problem. A1 documents the gap; A2 may add a `partial: true` flag or a warning header.
- **`schema_version` field on `CollectionMeta`** — open question; deferred to planning. If added in A1, every `CollectionMeta` constructor in tests needs an update — non-trivial blast radius.

## Key Decisions
- **Wire fields, don't just document them.** A1 = real extraction end-to-end. Documentation-only A1 shifts work into A2 and leaves the schema lying about its contents.
- **Grow `SearchResult`, not just `ChunkRecord`.** The brief's earlier framing of "surface fields in responses" understated the work — `SearchResult` is the choke point for both REST and MCP. A1 widens it.
- **`file_type` is the lowercased file-extension string without the leading dot** (`"md"`, `"markdown"`, `"py"`, `""` for no extension). No alias collapsing in A1. A2 filter callers pass the exact stored value. Negative test pins this decision against future normalization drift.
- **`ingested_by` enum values: `cli`, `http`, `watcher`, `reindex`.** The type annotation is `Literal["cli", "http", "watcher", "reindex"]` (4 members). The legacy stored value `"archon-search-cli"` from pre-A1 rows is **normalized to `"cli"` at the read boundary in `SearchStore`** (row-to-`SearchResult` and row-to-`ChunkRecord` mappings) so the `Literal` does not need to carry it; the on-disk bytes are left untouched and the normalization is a pure read-time projection. Reindex rewrites legacy values to `"reindex"` on disk. A2 filter docs will note that pre-A1 rows surface as `"cli"` until reindexed.
- **REST is additive, MCP is breaking; the `BREAKING.md` entry must distinguish them.** Strict-validating MCP clients see new keys; tolerant REST/JSON clients don't break.
- **Defer `language` entirely from responses.** Detection logic doesn't exist; faking it from file extension is misleading. Roadmap A2 amended in the same PR.
- **`vector` stripped from `search_with_context` context payloads.** Existing MCP behavior leaks the embedding via `asdict(ChunkRecord)` — A1 fixes this incidentally as part of the response-shape audit.
- **Partition map lives in code only.** CLAUDE.md says code is source of truth. The architecture doc gets a one-paragraph pointer, not a duplicate table.
- **Lazy backfill with opt-in CLI.** No auto-migration. A2 will inherit the "old rows have empty filter values" problem and must address it explicitly.
- **In-process per-collection lock map on `SearchStore` for reindex/ingest serialization.** New infrastructure, narrowly scoped to same-collection contention; other collections proceed in parallel. Cross-process safety remains a documented limitation.

## Edge Cases & Constraints
- **Existing collections after upgrade**: chunks have empty `file_type`, `updated_at` falls back to `indexed_at`, and `ingested_by == "archon-search-cli"` on disk but is **normalized to `"cli"` on read** so typed surfaces never see the legacy value. A2 filters on these dimensions return partial results until `reindex-metadata` runs. Documented as expected behavior; A2 owns any partial-result signaling.
- **Watcher re-ingest semantics**: re-ingesting a changed file calls `delete_document` then `ingest_chunks` (current `replace=True` semantics in `store.py`). New chunks carry the new `updated_at`; no stale duplicates because old chunks are deleted. A1 must add an integration test pinning this behavior so it doesn't regress.
- **File with no extension**: `file_type = ""`. Identical handling to "unknown" for filtering.
- **Mixed-case extensions** (`.MD`, `.Md`): lowercased at ingest (matches existing `parser.py:55`).
- **mtime unavailable** (piped stdin, vanished file, permission error): `updated_at = indexed_at`. Logged at DEBUG level.
- **Backfill on deleted source file**: chunk is preserved, `updated_at` retained from prior value (or set to `indexed_at` if it was empty), `ingested_by` normalized to `"reindex"`, a WARNING line is logged with the path. Tested.
- **Backfill on empty collection**: no-op, exits cleanly with `0 rows processed`.
- **Backfill idempotency**: running `reindex-metadata` twice produces **logically identical** chunk rows (field-by-field equality on all metadata fields) on the second run. Byte-level identity is not asserted because Lance's internal rowids and compaction state may differ.
- **Concurrent ingest during reindex**: ingest into the **same** collection blocks on that collection's lock until reindex completes; ingest into other collections is unaffected. Cross-process: not protected — documented.
- **`ingested_by` values**: typed as `Literal["cli", "http", "watcher", "reindex"]` (4 members). The legacy stored value `"archon-search-cli"` from pre-A1 rows is normalized to `"cli"` at the read boundary in `SearchStore`, so it never escapes into typed surfaces. Clients still sending `"archon-search-cli"` via `X-Ingested-By` are normalized to `"cli"` for backward compatibility (no WARNING log for this specific legacy literal). Other unknown values fall back to `"http"` with a WARNING log. New ingest sources must extend the literal + doc.
- **`X-Ingested-By` header values from clients**: validated at request time. Unknown values are coerced to `"http"` with a WARNING log; the request still succeeds. Rationale: clients should not be hard-failed on a metadata field they may not control, but the audit trail must remain trustworthy.
- **`custom_score` nullability**: PyArrow's `pa.field` defaults `nullable=True`, so the column is already nullable. A1 only adds the explicit `nullable=True` keyword for readability and pins behavior with a round-trip integration test (`None` written → `None` read back, not silently coerced to `0.0`).
- **`types.py` vs `_types.py`**: planning audit confirmed the two modules contain non-overlapping types (no `ChunkRecord` duplication). A1 takes no action here; the audit result is recorded in the plan.
- **MCP `asdict()` payload size on `search_with_context`**: stripping `vector` from context chunks reduces payload by ~`dim * 4` bytes per neighbor. A1 must NOT regress payload size; tested.
- **REST `SearchResultSchema` field optionality**: new fields are non-optional in the schema (always populated, with safe defaults for old rows: `file_type = ""`, `updated_at = indexed_at`, `ingested_by = "cli"` after read-boundary normalization of the legacy `"archon-search-cli"` bytes). Strict Pydantic validators on the client side will see new keys; tolerant ones won't break.
- **Eval harness coupling**: `tests/eval/` may construct `SearchResult` fixtures or assert on `asdict(result)` shape. Any such fixtures are updated in the same PR.

## Implementation Stacking Order (commit sequence)
The scope is wide; reviewability depends on a clean commit sequence. Implementation plan should follow this order, each commit independently reviewable and testable:

1. **Prep — `types.py` ↔ `_types.py` audit.** Planning has verified the two modules contain non-overlapping types; commit records the audit (no code change expected). No behavior change.
2. **Schema readability — explicit `nullable=True` on `custom_score`** + round-trip integration test. No data migration.
3. **Field wiring — parser → chunker → store** for `file_type`, `updated_at`, `ingested_by` (with `Literal` type). Unit tests for each call site. No response surface change yet.
4. **Response surface — grow `SearchResult`, `SearchResultSchema`** (including the existing-drift `acl` fix), add `parse_metadata()` to `hybrid_search`. Snapshot/contract tests.
5. **MCP audit — strip `vector` from `search_with_context` context payloads.** Payload-size regression test.
6. **Lock + backfill — `asyncio.Lock` on `SearchStore`, `reindex-metadata` CLI, `--dry-run`.** Unit tests for lock + dry-run; integration tests for reindex edge cases.
7. **Docs — `BREAKING.md` entry, `_types.ChunkRecord` partition-map docstrings, `130_data_architecture` pointer paragraph, `03_world_class_roadmap.md` amendment (drop `language` from A2).**

Each commit must independently pass the default pytest run.

## Recommendation
This is the right feature to build now: it converts three later items (A2 filters, C1 embedding model, C2 language) from "schema design + wiring + contract change" into "wiring only." The hardest part is **the response-shape change**, which is wider than the original brief implied: `SearchResult` itself must grow, `SearchResultSchema` must mirror it, and MCP `search_with_context` needs an explicit `vector`-stripping path. The second-hardest part is the **legacy `ingested_by` value** — A1 keeps `"archon-search-cli"` bytes on disk untouched but normalizes them to `"cli"` at the read boundary in `SearchStore` so the typed `Literal["cli","http","watcher","reindex"]` never has to carry the legacy member; reindex rewrites the bytes to `"reindex"` when invoked. What must not be compromised: **no half-built fields in responses.** `language` and `custom_score` stay on `ChunkRecord` for storage only and never reach `SearchResult` until they have real producers. The `Literal` annotation on `ingested_by`, the negative `file_type` normalization test, and the eval-harness regression check are the three guardrails that prevent A1 from rotting before A2 lands.
